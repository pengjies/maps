# 读书地图｜项目总 Guideline

## Version 1.0 · 2026-10-10 · 长期项目规则（每书独立，共享方法与 GIS 资料）

# 01｜项目目标与边界

项目目标：阅读历史、人物传记、旅行文学或相关作品时，把叙述中的时间、地点、路线与事件映射到真实地球表面。既能理解“当时的世界是什么样”，也能在今天定位、导航并尽可能亲自到达有关地点。  
三项基础能力：①按时间顺序在真实地图定位地点和活动（继承九州旅行地图的地理核对、轨迹与图例方法）；②找到并审慎使用对应时代的地形、河湖海岸线、聚落、政治/行政结构与可能道路；③把古地名、历史地点概念与现代经纬度、现代地名及可访问地点建立有来源的对应关系。  
核心表达：同一地球表面，不同时代的空间状态，以及发生在其中的人物行动。地图是理解工具与实地访问工具，而不是声称完全复原唯一的历史真相。  
项目采用“每本书独立保存阅读资料与专题成果，跨书共享人物、事件、历史地点和证据关联”的两层机制。书籍工作区不被合并；共享的历史时空索引只进行增量建设，不要求一次建成全量历史数据库，也不以系统建设妨碍真实阅读。

# 02｜地图产品与应用场景

基础用例 A：单一人物或团队的时间序列轨迹图（孔子周游、玄奘西游、苏东坡人生迁徙等）。按事件时间连接已考证的节点，提供章节与出处。  
扩展用例 B：多人物同期轨迹图（刘邦/项羽、曹操/刘备等）。同一时间切片展示多方位置、状态、行军方向、相距及地形障碍；时间精度不足时只比较“同一阶段”，不可虚构同一天的精确坐标。  
扩展用例 C：军事地理图（诸葛亮北伐、汉尼拔战争等）。在人物轨迹之外增加山川、渡口、古道、关隘、城池、补给节点、军队分路和敌方动态；严禁拿现代驾车导航直接冒充古代行军线。  
扩展用例 D：同一地点的历时演变图（汉/唐长安、晋阳、巴黎扩张、黄河河道演变）。可比较历史地点的范围、城址迁移、名称变更、城市扩张与今天的道路/遗址。  
扩展用例 E：历史实地访问地图。每本书最终有可导入 Google My Maps 的地点表；历史发生位置与今天的参观入口/观景点必须分开，避免为了导航而挪动历史坐标。

# 03｜时空数据原则

使用现代 WGS84 经纬度作为共享坐标参照。地点可以是点、线、面或“不确定范围”；古代空间边界不精确时，不能通过标一个精确 GPS 点假装证据充分。  
明确区分两条时间轴：地理时间（决定河道、城址、政区、道路采用哪个年代的重建）与事件时间（决定人物/事件/行军状态）。两者的资料精度通常不同，允许只精确到世纪、年代、年、季节、月或阶段。  
历史地名不是“古名＝现代城市名”的一对一表。至少分清四项：Place Concept（历史地点概念）、Historical Name（某时期的名称）、Temporal Footprint（该时期实际城址/范围）、Modern Referent & Access（今天的对应位置及可到达参观点）。  
处理同名异地、异名同地、城市迁建、县治迁移、河流改道、海岸线推进、遗址被淹没或不可访问。示例：汉长安城、隋大兴/唐长安城和现代西安彼此有关联，但空间范围不能简单视为相同。

# 04｜历史研究与可靠度

优先使用直接史料、可靠考古与学术研究；再使用学术历史地图、历史地名数据库、权威遗址资料；普通网站、百科与旅行资料可用于发现线索和现代访问核对，但不应单独支撑争议性历史判断。每个重要位置与路线都记录出处、版本、原文线索及解释。  
位置可靠度 A：考古遗址或多重独立证据明确对应；B：可确定城址/区域，但具体点不明；C：存在多个合理候选地点或路线；D：文学、传说或未经可靠定位的说法。等级描述“定位可靠度”，不是事件真实性、文本可信度和日期精度的合并打分。  
对争议不强行消解：地图可以同时保留 A/B/C 候选位置或路线，展示不同依据；不同候选对象使用稳定的假设 ID 和相同事件 ID 关联。未知数据留空并声明未知，不用插值和猜测制造确定感。  
文献要区分：历史事件、当事人记载、后世叙事、小说演义、地方传说。比如“六出祁山”是常用说法，但研究诸葛亮历史上的北伐必须另据史料分次；不能把文学叙述直接当成战役原始证据。  
推荐资料入口（逐案验证覆盖与版本）：CHGIS https\://chgis.fas.harvard.edu/ ；Pleiades https\://pleiades.stoa.org/ ；World Historical Gazetteer https\://whgazetteer.org/ ；OpenHistoricalMap https\://www\.openhistoricalmap.org/ 。这些来源的覆盖、时间精度与数据质量不同；均不自动等同完整的古代河道或古道数据库。

# 05｜历史行政、政治与边界表达

避免把不确定的古代政治空间涂成现代式、处处等强度的封闭色块。默认显示首都/郡治/县治、城镇、关隘、道路与行政隶属网络；对有可靠研究支持的正式政区可选择性显示范围。  
明确区分：法定/宣称行政范围、实际治理及赋税覆盖、军事控制、交通可达性和文化影响。它们的范围可能不同，不能互相替代。  
边界证据充足时可画明确线；大致已知时用透明面、渐隐、虚线或交错纹理；多种学说时允许并列。图例写明“重建”“大致影响区”“争议边界”，不得让样式暗示高于证据的精度。

# 06｜地图的三种主要视图

①现代定位视图：现代真实地形/道路/地名为主，叠加历史点位、历史轨迹及访问点。适合回答“今天在哪里、怎样到达”。  
②历史重建视图：选择一个地理时间切片，以该期河道、山川、古城、交通走廊、行政节点为主体；现代信息退居辅助。适合回答“当时的人面对怎样的地理约束”。  
③古今对照视图：同一坐标系上透明度叠加或左右滑动对比古今（必要时并列双视窗锁定相同中心/比例尺）。适合城址迁移、海岸线变化、河流改道和遗址重叠。  
默认以地形及历史自然地理为主，不同时开启所有信息层。可选图层：地形晕渲、历史水文（河道／湖沼／海岸线）、历史地名与城址、行政/势力网络、历史道路、人物/事件、现代地名道路、现代访问点、证据/候选方案。行政区与现代道路默认可隐藏；图层独立，研究主题优先。  
缩放分级：区域总览只标主要城市、关口、路线主干；城市级增加城墙、遗址与主要历史地名；街区级增加现代入口、街道、遗址范围。标签冲突时以主要研究问题为先，避免文字遮蔽地形。

# 07｜地图视觉与线路的约定

先核对地点相对位置与坐标，再生成地图；真实地理底图和可追溯 GIS 图层优先于 AI 绘制的“好看地图”。任何生成的示意插图不得被当作真实测绘底图。  
时间顺序明确：事件编号/时间与地图序号一致；反复到同一地点可以共用一个地点 ID，但每次访问保留独立事件 ID。路线按先后方向绘制，不应为了视觉简洁重排史实。  
线路语义：证据充分的实线；推定路线虚线；争议方案 A/B/C 分色或并排切换；未知段不凭空补线。古代河流/山脉/道路为背景信息，不与人物行军线共用相同图例。  
颜色原则：同一项目中每位人物采用稳定主色，路线方案采用线型+颜色双重编码；自然地理、政区、军事控制、现代交通各有不同视觉层级；图例、时间线、点位样式始终一致。  
每张成果地图标明：研究对象与来源书籍、地理时间、事件时间、底图来源、考证版本、图例和位置可靠度说明。可以制作静态总览和局部放大，但要保留真实地理关系。

# 08｜实地访问与 Google My Maps

每书固定导出“现代参观点”CSV（Google My Maps 导入）及适用时的 KML/KMZ（点/线/范围）。研究地图为主源；My Maps 是便于物理到访的轻量导出物，不保证完整保留时态 GIS、复杂图层或古地图叠加。  
CSV 至少包含：Name、Latitude、Longitude（WGS84 十进制度）、Historical\_Name、Period、Related\_Event、Reliability、Historical\_Location\_Note、Visit\_Name、Visit\_Access\_Note、Source\_URL、Map\_Link。CSV 标注 UTF-8；历史发生点和现代可参观点若不同，分别建记录并以 Related\_Place\_ID 关联。  
对每个旅游点标示“可实地访问／仅可外部观看／需要预约／不可进入／地点大致／无需特地前往”；只有确认存在且有可靠现代坐标的地点才能进入可导航清单。古代路线若无证据，不输出可导航的现代线路作为历史事实。

# 09｜项目组织、版本与验收

总项目根文件夹保留 Guideline、SOP 及可跨书复用的历史人物/事件/地点索引；每本书启动时创建独立子文件夹。建议每书内部按 01\_材料与出处、02\_地点和事件数据、03\_地图与候选方案、04\_导出与实地访问 四类存放；小项目可以暂不拆子目录。  
每本书可以交付：①历史交互专题地图；②一页或多页静态研究地图；③地点/事件/来源清单；④Google My Maps 可导入 CSV；⑤有需要时的 KML/KMZ；⑥待考证问题与版本变更记录。根据读书目标按需交付，不强制一次做齐。  
最低验收：坐标落点合理；古今名称关联有据；事件先后无颠倒；时间精度诚实；道路与河道不跨时代混用；争议假设未被误写为确定；图例一致；导出点能在现代地图独立复核。用户确认定稿后再替换旧版本，并保留必要版本记录。

# 10｜首批验证用例与演进

Pilot 1：汉长安—隋唐长安—现代西安的空间演变。验证相同坐标下的时代切换、古今对照、位置重叠与标签密度。  
Pilot 2：诸葛亮公元228年第一次北伐。验证古代城址/道路、时序轨迹、疑军与主力分路、争议路径、军事环境和导出今日可访地点。  
发展原则：每读一本书完善少量规则，再更新本 Guideline/SOP 的版本。不要为了理论上的万能地图系统耽误实际阅读。

# 十一｜跨项目共用收尾：地理收藏（2026-10-17）

本规则适用于所有地理项目，包括历史阅读、漫画实景、旅行、餐饮及后续新增项目。专题阅读原始材料仍按每书独立维护；跨书历史人物/事件/地点索引按本项目规则复用，而地理收藏另按统一手册关联现实地点与收藏理由。新地理项目创建 SOP 时，必须把以下调用段置于操作流程最后一步。

主动列出本批搜寻并记录的每一个地点，询问：“这些地点要把哪些加入地理收藏？标签沿用哪些，要不要新增标签？”地点多时合并成一张短清单供全部／部分选择，不能只推荐少数点；已收藏的标为新增理由／标签或已有无新增。

明确同意后，读取下列统一手册的最新 SOP 与总表，携带来源项目、原始记录链接／ID、现实地点与坐标依据或待定位状态、作品及已读范围、收藏理由和已确认标签，按其规则去重入库；返回本项目说明结果。已明确授权的事项直接执行，未答复或拒绝不默认入库，也不阻断本项目完成。

优先复用既有标签；需要新标签时让用户确认名称。同一地点可关联多个作品／理由／标签；地理收藏是各项目的标准步骤，无需用户另开项目或重发材料。收藏确认只更新资料，不自动生成部署包或发布网站。

[统一手册（固定引用，读取最新版本）：地理收藏｜Guideline 与 SOP](https://docs.google.com/document/d/1xADDMJEZjhIFRiqOcL_LBEM2GTsWqxPt5cr3WKsNAcw)

完成检查增加：本批全部地点是否已发起收藏及标签询问？每项是否标明待选择、暂不收藏、已新增、已补充或已存在无新增？凡声称已收藏的，是否已按统一 SOP 写入并核验？以后收藏／展示细节集中在统一手册修改，本项目保留调用入口并检查兼容。

十二｜跨书籍人物生平与历史时空索引（v1.1，2026-11-10）  
核心模型：Source（书籍、版本、章节/页码及原始断言）→ Person（跨书稳定人物 ID）／Event（可跨人物引用的历史活动或事件 ID）／Place（历史地点概念与候选位置）→ Map View（按人物、时期、事件或书籍生成的地图）。地图是数据视图，不是唯一数据源。每本书仍保留独立原文与研究笔记。  
人物档案允许不完整、不连续和乱序更新。每次阅读抽取所涉及人物，不论其是否为该书主角；先查重、关联 Person\_ID，再以原文时间、标准化时间起止范围、时间精度及时间不确定性插入人物年表。只有年份、时期、前后次序的史料不补造具体日期。  
同一事件可以连接多个人物、多条来源证据与多个有依据的地点/路线假说。保留 Source\_Assertion\_ID、Source\_ID、Person\_ID、Event\_ID、Place\_ID、Hypothesis\_ID 的关系；同一事件的新资料是新增证据/修订判断，不是覆盖旧来源。史书记载、后世解释、文学叙事及当前研究判断必须可辨。  
位置可靠度、事件真实性、史料可信度、时间精度、路线可信度分开记录，不合成为单一等级。对争议、时间不明或地点未定的活动仍予保留；不得为视觉连续性直接连接两次已知出现的地点，未获支持的中段应留白。  
共享数据按实际阅读逐步维护，优先简单、稳定 ID 与关系表；不强制立即搭建统一前端或迁移现有孔子/伍子胥项目。新增地图可通过筛选人物、时期、事件、来源自动衍生单人生平、多人同期及事件专题视图；同时显示数据覆盖与缺失。  
边界：历史时空索引用于复用史料和考证，不替代《地理收藏》个人想去地点的手动确认、标签、去重及发布 SOP。每批阅读完成后仍执行现有地理收藏询问。

十三｜地形优先与历史水文时间切片（v1.2，2026-11-13）  
研究目标：优先解释历史人物为什么在某地活动、如何跨越山川、为何某城或渡口具有战略意义。现代行政区划只作为检索、现实访问和数据表字段，不默认占据历史阅读地图。地图显示与 Google Sheets 地理收藏记录分工明确。  
底图：历史阅读默认选择能够突出山脉、盆地、坡度和河谷的地形晕渲（Hillshade）或已有 OpenTopoMap；保留 OpenStreetMap 标准底图作为现代定位辅助。Google Maps Terrain 是可选的技术评估目标，必须先核对 API 接入方式、授权、计费、地区可用性及与现有 Leaflet/HTML 的兼容性；严禁未经授权抓取 Google 瓦片，不将候选功能写成已上线。现实旅行视图可切回现代道路和地名。  
地貌分层：大型山脉、盆地、高原轮廓可参考现代 DEM；黄土沟谷、滑坡坡脚、河岸冲积地貌与现代工程影响需局部复核。历史河道、湖泊、湿地、海岸线及渡口不能直接沿用现代水文。古城、港口、关隘、古道应以事件年代对应的自然环境考证，不拿现代河岸或道路自动推导古代交通。  
时间：把现代地形骨架与按年代管理的历史水文图层解耦。历史水系记录 Historical\_Feature\_ID、名称／类别、几何或不确定范围、有效年代及时间精度、来源与版本、定位可靠度、争议假设、与现代要素的关系及适用地图范围。历史水文与人物 Event\_Time 联动时，先按有效期及证据选取可用时间切片；没有对应切片应标注“历史水文资料缺失”，现代水系只可作为标明年代的现代参照。  
禁止伪精度：不能根据不同时代的两套河道数据自动内插生成中间每年的“真实河流”。历史水系重建有争议时并列候选并显示范围／来源；没有几何依据不画精细河岸。湖泊湿地可以是季节性、漫滩及多个水体组成的系统，不默认画成永久、边界封闭的一片湖。  
研究数据积累：优先查阅直接史料、学术历史地图、考古及古水文／沉积地貌研究；合法复用可追溯 GIS 数据。按地区和时段逐步建立共用历史自然地理图层，先不承诺全国逐年完整数据库。优先试点：汉中—关中（山地通道）、荆州—江汉平原（古水网湖沼）、黄河下游—中原（改道及渡口）。  
验收：核对底图授权和真实地形；事件年份与历史水文有效范围相容；古代渡口/城址不以现代河岸代替；图层说明显示证据与不确定性；现代行政区可隐藏但表中仍保留；未完成图层及前端功能明确标注待实现。
