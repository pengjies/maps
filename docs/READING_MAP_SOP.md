# 读书地图｜聊天窗口地图 × KMZ × Google My Maps：统一操作 SOP

> **版本**：v2.0 · 2026-11-21  
> **适用**：历史地理、人物生平、史料辨析、漫画／文学现实场景、实地旅行准备。  
> **当前默认**：**ChatGPT 窗口地图即时定位和讨论 → 用户确认 → 当场原位更新该作品唯一 KMZ → 进入下一地理；My Maps 仅在需要时重导入。**  
> **原则**：一套经过核实的研究记录，多种地图展示；不以地图“看起来有点”代替有证据的历史地望，不把地图显示等同于永久保存。

## 0. 本版优先级和三种地图的职责

本版融合 Google Drive 既有《项目总 Guideline》《阅读到地图的操作 SOP》《My Maps 与 Google Earth 专题地图 SOP》，以 **2026-11-14 新增“双轨工作流 v1.2”** 为最新执行优先级。既有文档中“每次读书默认先导入 My Maps 才能看”的表述已被本版取代，历史研究要求不变。

| 介质 | 角色 | 更新方式 | 是否为永久资产 |
| --- | --- | --- | --- |
| **ChatGPT 窗口交互地图** | 正在读的地名、候选点、山川和相邻地点的即时可视化与讨论 | 按当前问题重新显示和调整 | **否**：不保证各轮共用同一持久地图 |
| **KMZ（Google Drive）** | 每部作品唯一、可移植、持久的地点／事件／路线／候选几何交换包 | **确认后立即合并，并原位覆盖相同 Drive 文件 ID** | **是**：正式地图交付主档 |
| **Google My Maps** | 需要全专题集中浏览、跨设备查看、分享或实地访问时的图层化地图 | 按需导入或更新已有图层，核查重影与重复 | **是，但只是展示副本**，不自动跟随 Drive 更新 |
| Google Earth | 卫星影像、三维地形观察 | 从 My Maps 查看或导入 KMZ | 按使用模式可能是独立副本，**不自动反向同步** |
| 原 Leaflet / HTML 研究地图 | 古今水文、DEM 彩色高程、跨时代图层、复杂自定义交互 | 研究需求明确时专项维护 | 保留旧成果，不为每一处新地名强制制作 HTML |
| 地理收藏（独立 Sheet） | 现实世界值得访问地点的跨项目索引 | 用户逐项授权后独立去重、更新 | **是，但不是 KMZ 的同义词** |

**三条不能混淆的边界**：窗口地图显示 ≠ KMZ 已写入；KMZ 已更新 ≠ My Maps 已同步；KMZ 的古城代表点 ≠ 现实世界可导航的遗址入口。

## 1. 每个地点的标准工作闭环（必须依序）

### Step 1 — 从正在阅读的材料识别地理

1. 记录来源书名／章节／页码（可得时）、原始论断、人物、事件和相应年代；检索是否已有 `Place_ID`、`Event_ID`、`Person_ID`。历史人物年表允许乱序增补，不强行按阅读顺序修改历史事件时间。
2. 区分历史地点概念、某时代的历史名称、该时代真实城市／地域范围、今天的现代参考位置及现实游客入口。谨防“古名 = 今日同名城区”式误判。
3. 通过史料、考古、历史地理研究与历史地名系统等资料核查坐标和争议。没有依据的经纬度留空；不能把现代河道、道路、桥梁、港口当作古代同一地点／线路。
4. 使用 WGS84 坐标；点、线、面、候选范围可以共存。**古城地望可靠度**、**事件本身可靠度**、**人物是否亲历**、**时间精度**、**路线几何可靠度**必须分别表达。

### Step 2 — 先在 ChatGPT 窗口地图显示和讨论

1. **优先直接展示交互式窗口地图**，不是静态图片、手绘示意图，也不要求先制作 HTML 或导入 My Maps。地图应显示正在讨论的地点及少量有助理解其空间意义的已有点／自然地理参照。
2. 地望有争议时允许多个候选点同时出现；明确显示“候选”“区域代表点”“现代参照”“遗址范围”，不能用精确图钉假装古代城墙或宫室精确测绘点。无可核实坐标时只进行文本考证，必要时保留待定，不为了出图虚构坐标。
3. 讨论空间关系时强调山岭、盆地、河谷、历史水系和实际地势。窗口地图本身的现代底图只作为现代空间参照，**不提供未经核实的古代河流、政区或道路复原**。
4. 对同一问题按用户纠正实时调整窗口地图。保留名称、当前年代、坐标性质、证据等级和出处的简短说明；不默认使用毫无意义的展示顺序编号作为图钉标签。
5. **路线箭头不是必需品**：只有确切的行动前后关系、事件关系或经考证的道路，才考虑以明确语义展示；“阅读顺序”“史料支持的前后关系”和“历史真实行军道路”不得相互冒充。

### Step 3 — 确认再写入

与用户就本次地点达成明确结论：

- `已确认地望`：地点、代表点性质、时代、来源和定位精度已经足以入档。
- `暂定工作地望`／`并列候选`：用户认可带争议地写入；务必保存候选状态、解释、来源及不可确定之处。
- `待考证`：存在实质争议、无坐标或用户尚未确认；保留研究笔记，**暂不作为“已确认地点”写入正式 KMZ**。

确认对象应含 `Place_ID / Event_ID`、中文历史名及异名、现代对应、坐标、几何类型、时间、人物或事件关系、至少一项来源和证据说明。用户就路线／区域范围确认时，同样明确该几何的意义。

### Step 4 — 立即更新唯一 KMZ 主档

1. **先从 Google Drive 获取该作品当前最新 KMZ**，不能用旧会话中的本地文件或先前导出版本覆盖较新的修改。读取 `doc.kml`，建立现存 `Place_ID / Event_ID / Segment_ID` 清单，确认旧点旧线旧说明数量。
2. 合并本次确认的新增或修订记录：新增保留全部原有地点、事件、路线；已存在的 ID 更新对应内容，不做重复点；争议方案可分别保留并关联同一历史地点概念。
3. KML 文档需保留地点 `Placemark`、必要 `LineString`/`Polygon`、`description` 和 `ExtendedData`；历史位置不确定性应出现在**打开图钉首先可见的描述中**，不仅藏于扩展字段。
4. 用标准 `.kmz` ZIP 包装 `doc.kml`；执行 XML 解析、坐标经纬顺序、地点/线段数量、唯一 ID、UTF-8、链接、特殊字符、历史证据说明检查。KML `Point` 坐标是 `经度,纬度,高度`；注意与 Leaflet 的 `[纬度,经度]` 相反。
5. **更新原 Google Drive 文件的二进制内容，保持文件 ID 与正式文件名不变**；利用 Drive 修订历史回退。不能每新增一个点生成永久的 `v1/v2/v3` 平行主档。若是首次创建的专题，则先创建唯一主档一次。
6. **再从 Drive 回读文件元数据／相关内容核验成功**，记录最后更新时间、地点与线段计数。无法写入或核验失败，必须明确汇报“已在窗口地图讨论，但 KMZ 尚未成功更新”，不得宣称已经保存。
7. 当场向用户简要确认新增什么、保留什么、KMZ 是否更新成功和链接，然后才进入下一个地点。**不积压到整本书读完后统一转存。**

### Step 5 — 独立询问“地理收藏”

所有实际识别的地点都按现有《地理收藏》SOP 询问是否收藏，以及沿用／增加什么标签；一次可询问数个地点，但每处必须有独立决定。既有地点先查重，可补充新作品和理由。未得到明确同意不写入；收藏与 KMZ 落盘是两条独立流程。需要旅行时另查遗址是否仍有现实实物、是否开放以及实际参观入口。

### Step 6 — 开始下一个地点

读取当前已确认的基线；在下一轮窗口地图中按研究问题选择有用的旧点作空间参考。**窗口地图无需自动累积永久状态**；长期主数据以来源表、研究档案和最新 KMZ 为准。

## 2. 关键数据字段（最小可执行模型）

| 字段 | 含义 |
| --- | --- |
| `Project_ID / Book_ID` | 专题与出处作品 |
| `Place_ID` | 全局地点 ID；作品内可另有 `P_ID` |
| `Historical_Name / Aliases` | 历史地名及同名异名 |
| `Temporal_Footprint / Event_Time` | 地理有效年代和事件年代／精度分开 |
| `Modern_Referent` | 对应的现代地理区域、城市、遗址或场所 |
| `Latitude / Longitude (WGS84)` | 明确是确址、工作代表点还是候选点 |
| `Geometry_Type / Geometry_Status` | Point / LineString / Polygon；区域或代表点性质 |
| `Geographic_Confidence` | 地望证据等级 A/B/C/D，明确依据 |
| `Event_ID / Person_ID / Participation_Confidence` | 事件和人物关联；不以事件存在推断人物亲历 |
| `Source_ID / Source_URL / Source_Assertion` | 书籍章节、原始史料与考古／地图资料 |
| `Route_Type / Route_Evidence` | 无路线、先后关系、阅读示意、确证古道等 |
| `Status / Verified_At / Updated_At` | 已确认、暂定候选、待考证；核实日期与版本 |
| `Visit_Point / Visit_Class` | 现实旅行点／入口及可参观类别，和历史点分别记录 |

### 地望等级口径

- **A**：有可靠遗址或多重独立证据明确对应；仍不等于每个建筑的确址。
- **B**：城址或区域较可信，但内部具体点位未知。
- **C**：多个合理候选或定位争议尚存。
- **D**：小说、传说或缺乏有效地点证据；可保留文化地理背景但不伪装实测。

等级只说明**地理位置证据**，不能代表事件发生概率、人物是否到访、时间精度或道路真伪。

## 3. 路线、箭头和历史自然地理

对每段拟绘制的线，先确定 `from` / `to`、起止年代、人物归属、来源和语义：

| 模式 | 默认处理 |
| --- | --- |
| 地点分布／证据不足 | **不画线** |
| 有据的前后到访或迁移 | 可画方向关系，说明“节点顺序，非具体道路复原” |
| 作品阅读顺序／相关事件 | 只画**可关闭的示意图层**，明确与真实历史路线区分 |
| 具有独立可信几何证据的古道／行军走廊 | 单独实线或相应可靠性标识，保留年代与来源 |
| 存在多种地望或路线学说 | 并列候选，不擅自合并成一条精确路径 |

大型山脉、盆地可参考现代真实地形 DEM 作为地势骨架；古河道、湖泊、湿地、海岸线和渡口应依据**事件所属年代**构建带有效时间范围的数据，缺失时标注“历史水文资料缺失”。不自动按两个已知时代的河道推导中间逐年变化。

原 Leaflet / HTML 中对 DEM 彩色高程、晕渲、历史政区与古今水文的实验结果继续保留；**这些数据或渲染效果不能假设 ChatGPT 窗口地图自动具备**。窗口地图以适合当前比较问题的点/路线/空间参照为主。

## 4. Google My Maps：按需发布，而不是每一点重复导入

### 首次发布

1. 打开 [Google My Maps](https://www.google.com/maps/d/)，新建该作品**一张**专题地图，手工核对地图标题及图层名。
2. 从当前唯一 KMZ 导入“历史地点”图层；点、线、候选面如要独立开关，可从主档临时拆出单独导入资料。临时文件不作为第二份永久主档。
3. 核对实际导入点线数量、坐标、描述、来源、候选标识、图层开关。确认手机端 Google Maps 的“用户地图”中是否可见时，另记为**已验收**，不要把“文件上传”说成“已显示”。
4. 需要研究真实地形可在 Google Earth 查看相应专题；Google 现代地形／卫星显示不是古代水文重建，也不等于 DEM 彩色海拔分级。

### 之后何时更新

- **日常阅读**：窗口地图即时讨论；确认后更新 Drive KMZ。此时 My Maps 可以落后于 KMZ，**不阻断继续阅读**。
- **用户主动要求完整专题、跨设备查看、旅行或分享**：在已有 My Maps 里重导入／替换受影响的图层，检查旧数据没有重叠或重复；通常不重建整张专题地图。
- **绝不宣称自动同步**：Google Drive KMZ 的变化不会自动推送至 My Maps；My Maps 独立修改也不会自动写回 Drive 或聊天窗口。必要时维护更新日志和同步状态。

My Maps 每个专题最多 10 图层；KML/KMZ 复杂样式、箭头尖端、多个 KML Folder 不保证按原样变为 My Maps 可独立开关图层。图层能力和导入限额以使用时 Google 最新说明及实际验收为准。

## 6. 完整验收 Gate 与汇报口径

| Gate | 要确认的事实 | 未完成时应如何说 |
| --- | --- | --- |
| A：讨论 | 位置真实可见于聊天地图，候选与坐标精度正确 | “地点仍在考证／地图未能显示” |
| B：研究 | 用户明确确认地望、工作候选、事件或线路语义 | “尚未确认，不入正式 KMZ” |
| C：归档 | 旧 KMZ 完整保留；新增合并；`doc.kml` 与坐标/数量校验通过；原 Drive ID 原位保存并读回 | “已讨论，但 KMZ 还未更新” |
| D：发布 | My Maps 实际重导入并核对，不是仅有 Drive 文件 | “Drive KMZ 已更新，My Maps 尚待重导入” |
| E：收藏 | 每处新地理已询问是否入地理收藏；用户批准的才去重写入 | “已询问／待用户选择” |
| F：实地 | 考古研究点与现代可到访的景区入口、开放情况分开核实 | “历史地望，不可直接按此图钉导航” |

**每一地点完成时的简短回执模板**：

> 已确认／暂定：`地点名（Place_ID）`，代表坐标性质：`…`，来源：`…`。本轮窗口地图已展示；Drive 主档 `作品名.kmz` 已在原文件 ID 上更新（点 `N`、线 `M`），My Maps 当前 `已同步 / 尚待重导入`。地理收藏：`已收藏 / 已询问待确认 / 不收藏`。

如果工具不可用，应将上述字段改为真实状态，不能在未核验时宣称写入成功。

## 7. 例外与失败处理

- **只有地名、无可核实坐标**：保留史料讨论和研究表，不强制出假图钉；用户仍可继续阅读其他地点。
- **同一地理有多个时代或位置候选**：共享地点概念 + 不同候选几何/年代，窗口地图并列显示；KMZ 描述保留哪一种是假说及依据。
- **KMZ 原档无法下载或写入**：停止对该主档覆盖，保留当前已确认的研究结论和可交付临时文件，明确未完成；恢复访问后先检查最新 Drive 修订，防止覆盖别人已更新的资料。
- **My Maps 图层限额或导入失败**：先用正式 KMZ 维持数据完整，按需拆分临时导入文件、合并图层或改用 CSV/Sheets 适当同步；不把重复导入产生的图钉误当为新增历史地点。
- **窗口地图不能展示复杂历史 GIS**：只显示有据可考的点和必要路线，继续使用原 HTML / DEM 专题呈现历史河网、政区和地形，不伪称 ChatGPT 内建地图已有历史分层系统。
- **旧研究被新资料推翻**：保留来源断言及修订原因，更新位置和争议状态；不能静默抹除旧证据。
